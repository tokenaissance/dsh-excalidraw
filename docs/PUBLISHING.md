# Publishing dsh-excalidraw

DSH has no private app store: a plugin "is listed" when it **installs with
`dsh plugin add`** and appears in the community catalog. Three independent
surfaces read the same package:

| Surface | What it needs |
| --- | --- |
| DSH Plugin Manager (**Settings → Plugins → Add plugin**) | a package name (npm), a Git URL, or a local directory |
| dsh-market / **Plugins → Discover** | an entry in the curated catalog (see below) |
| npm | a published package (optional but recommended) |

This package already carries what the Plugin Manager reads before activating a
plugin: `dsh.bundle.patch` (installable bundle), `locale/en.json` and
`locale/zh.json` (`meta.title` / `meta.description`) and an exported `./icon`
(SVG, < 1 KiB). `files` includes the patch, both locales, the icon and every
runtime file.

## 1. From a directory or a tarball (no registry)

```sh
npm pack                                  # produces dsh-excalidraw-0.1.0.tgz
dsh plugin --profile desktop add ./dsh-excalidraw-0.1.0.tgz
# or a checkout / link:
dsh plugin --profile desktop add file:$PWD
```

Then restart DSH (or accept the Plugin Manager's HMR restart prompt). The
bundle's own patch inserts the `excalidraw` row, so nothing else is needed.

## 2. From GitHub (no npm account)

Push the tree to a repository that keeps `dsh.bundle` in `package.json` and a
`cordis.patch.yml` next to it, add the **`dsh-plugin`** GitHub topic, and users
install:

```sh
dsh plugin --profile desktop add "github:<owner>/dsh-excalidraw"
```

`client.js` is committed, so a Git install needs no build step.

## 3. From npm (recommended for the market)

```sh
npm login                                  # once per machine
npm publish --access public                # package.json has publishConfig.access=public
```

`prepack` rebuilds `src/fonts-data.mjs` and `client.js` before packing, and the
packed file list is the `files` array (61 files, ~310 kB). Check the result:

```sh
npm pack --dry-run
npm view dsh-excalidraw version
```

Users then install by name:

```sh
dsh plugin --profile desktop add dsh-excalidraw
# or: Settings → Plugins → Add plugin → dsh-excalidraw
```

pnpm 11 applies a `minimumReleaseAge` window (about a day) to newly published
versions, so a plain `add dsh-excalidraw` resolves the previous release right
after a publish. To take a fresh version immediately, pin it — pnpm then adds its
own `minimumReleaseAgeExclude` entry for that exact version:

```sh
dsh plugin --profile desktop add dsh-excalidraw@0.1.1
```

## 4. Get listed in the community catalog

The catalog behind **Plugins → Discover** and [dsh-market](https://github.com/dsh-market/dsh-market)
is the curated [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)
list. Open **one PR** adding one YAML file, `data/plugins/<owner>__<repo>.yml`:

```yaml
url: https://github.com/<owner>/dsh-excalidraw
name: <owner>/dsh-excalidraw
category: docs
description:
  en: Renders a live Excalidraw architecture scene in DSH and refreshes it from Excalidraw+ over MCP.
  zh: 在 DSH 里渲染实时 Excalidraw 架构图，并通过 MCP 从 Excalidraw+ 刷新。
```

(The filename's `__` separates owner and repo. `category` values are listed in
that repo's `contributing.md`; `docs` is the rendering bucket.)

Requirements from that repo, all of which this package meets or can meet:

- `dsh.bundle` in `package.json` with a real `cordis.patch.yml` — yes
  (`dsh.bundle.patch` accepts a file or an ordered list, and this one is a list);
- real working code, not a placeholder — yes;
- repository at least one day old, maintained, `dsh-plugin` topic — repository
  side, not package side;
- an accurate one-line description — the `description.en` above is checked
  against the code: the plugin renders scenes through `renderScene` and pulls
  them with `excalidraw_refresh` over the Excalidraw+ MCP endpoint.

After merge the site and dsh-market pick the entry up automatically (usually
within a day); nothing is regenerated by hand.

## 5. Verify before announcing

```sh
npm test                                   # 212 tests, no build
dsh plugin --profile <fresh> add <source>  # npm name, github:…, or a tarball
```

Then in the Plugin Manager: the row shows **Excalidraw** (`Excalidraw 图` in
Chinese) with this package's description and icon, `settings` opens the cordis
config form, and the capability works: send a message in a workspace, ask the
agent to refresh a scene, and the view appears in the sidebar (better-sidebar)
or as the **Excalidraw** conversation view (stock DSH).
